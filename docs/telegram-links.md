# Telegram-ссылки после взаимности

Проверено 9.11.2026 через аккаунт владельца в официальном @jardulik_bot и по публичной сборке index-BFeBP-cW.js.

1. Экран взаимностей получает список через GET /user/getReactUsers с isMutual=true.
2. Кнопка Telegram вызывает POST /telegram/getTG с внутренними fromUserId и targetUserId Jardulik. Это действие запрашивает отправку карточки, а не обычное чтение JSON анкеты.
3. Frontend не использует ответ как контактный URL: после запроса он закрывает Mini App. Контактная карточка видна в личном диалоге с официальным ботом.
4. Посмотреть анкету является web_app-кнопкой с URL вида https://mini.jardulik.app/mutuals?targetUserId=<id>&noCheck=1. Telegram добавляет свежие подписанные launch-параметры. noCheck=1 не доказывает взаимность; для маршрута mutuals frontend его не использует.
5. Открыть в Telegram содержит отдельную обычную ссылку https://t.me/<username>. Проверенный переход открывает личный диалог.

Связь ID Jardulik с Telegram numeric ID не выводится из номера анкеты или username. Шаблон start/startapp для произвольной анкеты в просмотренной сборке не подтверждён. Кнопка запуска от другого бота не эквивалентна запуску от официального Jardulik: подпись launch-данных относится к боту запуска.

## Хранение

profile_contact_evidence сохраняет контакт, точный URL исходной web_app-кнопки без launch-фрагмента, аккаунт Jardulik, профиль и locator исходного сообщения. Тип official_bot_ui означает операторское наблюдение в интерфейсе, а не криптографически проверенный ответ Jardulik API. data-mid хранится как непрозрачный DOM locator и не объявляется серверным Telegram message_id.

Наблюдение импортируется JSON через stdin:

```sh
jardulik import-contact < evidence.json
```

Команда доступна только настроенному оператору и проверяет текущий upstream аккаунт, доверенный source bot, URL и привязку профиля. Сетевых запросов она не делает. Повторный импорт идемпотентен; изменение URL сохраняется отдельной записью. Контакт показывается отдельной кнопкой в личке, только для соответствующего владельца и текущего аккаунта. Исходный JSON анкеты не меняется. Новые контактные данные включены в fingerprint суточного бэкапа.

## Приём новых контактов

Парсер принимает `business_connection`, `business_message` и `edited_business_message` через существующий long polling. Сначала владелец подключает свой Jardulik через `/connect`. Затем в BotFather включают поддержку Business у Companion, и владелец подключает его к выбранному чату официального Jardulik. Эти настройки доступа не включаются автоматически при деплое.

Владелец определяется по `BusinessConnection.user.id`. Подключение закрепляется за текущим аккаунтом Jardulik и поколением его сессии. Новая сессия требует нового подтверждённого события подключения; старое подключение не переносится между аккаунтами. Сообщение должно прийти непосредственно от числового `JARDULIK_BOT_ID` в его приватном чате, без пересылки и отправки другим Business-ботом. Остальные чаты не записываются.

Парсер связывает одну однозначную пару ссылок в клавиатуре карточки: исходную кнопку `/mutuals?targetUserId=…&noCheck=1` и контакт `https://t.me/<username>`. Точный входящий JSON и контакт сохраняются одной транзакцией в `profile_business_contacts`, отдельно от серверного JSON анкеты. Контакт можно получить до загрузки самой анкеты. Дубли Telegram updates не создают повторные записи, изменённая ссылка сохраняет историю. Подтверждение offset идёт после записи: ошибка SQLite останавливает обработку, чтобы Telegram мог повторно доставить update.

Приём не отправляет сообщения от лица владельца, не отмечает их прочитанными и не вызывает `/telegram/getTG`. Показ сохранённого контакта использует только БД. Уже найденный контакт остаётся в архиве после отключения Business-чата, но скрывается при отключении или смене Jardulik-аккаунта. В суточный fingerprint входят контакты и состояние подключения; повторное чтение или технический повтор того же контакта не считается обновлением.

Сам `getTG` остаётся отдельным штатным действием после взаимности. Frontend игнорирует его тело ответа; наличие Telegram URL в этом ответе пока не проверено. В просмотренных сохранённых полных анкетах и списке взаимностей поля контакта не было. Обычный обход каталога не раскрывает недоступные контакты.

Приём через реальное Business-подключение и сохранность клавиатуры в нём требуют проверки после подключения. Существующий MTProto helper авторизован как наш бот, не как пользователь.
