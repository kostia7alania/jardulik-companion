# Посты в архивных тредах

В первой строке общей карточки появляется `⭐ Premium`, если Jardulik прислал `type=1`. Это тариф Jardulik; Telegram `is_premium` не участвует. Карточки лички, архива и rich-message используют один `profileText`. Ранее отправленные карточки обновляются существующим воркером caption maintenance без повторной загрузки фотографий и без изменения исходного JSON.

После новой опубликованной версии отдельный пост поясняет разницу с предыдущей подтверждённой публикацией того же профиля. Он показывает изменившиеся поля, Premium, фотографии или миниатюры. Расстояние и состояние реакции наблюдателя не считаются изменениями анкеты. Формулировка описывает разницу ответов сервера, а не приписывает человеку ручное редактирование.

Сохранённый успешный ответ `/GPT/checkCompatibility` появляется отдельным постом в существующем треде. Явная однозначная оценка совместимости может отображаться в заголовке; это цитата из ответа Jardulik, не новая числовая метрика БД. В заголовке указывается точное сообщённое сервисом имя модели. `content` помещается в свёрнутую цитату; Markdown-пары `**...**` отображаются жирным. Исходные байты ответа в БД и JSON-экспорте сохраняются. Если ответ превышает лимит Telegram, пост содержит точное начало, явное указание продолжения и кнопку полного JSON в личку владельцу. Экспорт сохраняет точные байты `response_body` в `.json`.

Эти отправители входят в роль `serve-poster`, читают только сохранённые данные и не запускают дополнительные запросы GPT. Публикация расчётов пока ограничена `Config.OwnerID` и текущей привязкой его Jardulik-аккаунта. Полный JSON доступен тому же владельцу; чужой пользователь и прежний upstream аккаунт не проходят проверку callback.

Уведомления об изменениях и расчётах используют отдельные журналы отправки. Подтверждённая отправка содержит Telegram message ID; незавершённая подготовка безопасно возобновляется, а неопределённый результат HTTP сохраняется для сверки без автоматического повторного поста. Фактическая очередь использует общий архивный mutex и групповой лимит Telegram.

Пока анкета недоступна или ожидает доставки событие доступности, расчёты и пояснения не добавляются в её тред. Это сохраняет уведомление о недоступности последним. Существующие посты и архивы не удаляются.

Новые таблицы целиком входят в SQLite-бэкап. Ежедневный fingerprint по-прежнему меняется от исходных анкет и GPT-ответов; повторные попытки доставки не создают бэкап без новых данных.


Дата и время в представлении используют общий префикс `🕒`; дата рождения остаётся с `🎂`. Caption maintenance обновляет подтверждённые старые карточки, GPT-посты, пояснения и события доступности через edit существующего message ID. Новая редакция заменяет только ещё не выполненные задания старого дизайна; исходные сообщения, фотографии, JSON и даты наблюдений сохраняются.

Для обычного `Like=1` доступно собственное сообщение до 500 UTF-16. Настройка владельца: `off`, `first`, `rotate`, `birthday`; изначально `off`. Birthday выбирает из 144 игровых вариантов по календарной теме знака и 12 нейтральных. Неточная/отсутствующая дата и пограничные дни дают нейтральный текст. Human Design и натальные положения не вычисляются без нужных данных. Текст, полный request, индекс и политика сохраняются в отдельном intent до единственного POST. Неопределённый результат не отправляется заново; существующие ограничения возраста, фильтров, квоты и интервала сохраняются. DTO и код клиента допускают текст для `Like=1`, но показ получателю на втором согласившемся аккаунте отдельно не проверялся.

Изменения фото показываются без дублирования превью и нулевых счётчиков: `фото: добавлено: 1`, `фото: убрано: 1` или `фото: добавлено: 1, убрано: 1`. Для сравнения используются оригиналы, а при изменении только миниатюр их результат служит одним запасным источником этой же строки. Исходные SHA, роли, позиции и JSON сохраняются раздельно.

Одноразовый scope `caption_notice_revision=2026-11-10-rating-short-photo-v1` дополняет основной прогон v3: он подхватывает подтверждённые уведомления `change`, опубликованные после первого snapshot, и перепроверяет заголовки `analysis` через общий разбор итоговой оценки. Повторный запуск не сбрасывает выполненные задания. Правятся прежние message ID; карточки, ZIP и события присутствия этот scope не перепланирует.

Воркер исправлений получает следующий общий Telegram slot после атомарного claim и проверяет receipt/source после ожидания. Будущий checkpoint сам по себе не означает отсутствие работы: это предотвращает голодание при непрерывной публикации анкет. Один проход делает один edit; HTTP429 сохраняется для последующего retry, как и раньше.
