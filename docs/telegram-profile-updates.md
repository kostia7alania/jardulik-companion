# Посты в архивных тредах

В первой строке общей карточки появляется `⭐ Premium`, если Jardulik прислал `type=1`. Это тариф Jardulik; Telegram `is_premium` не участвует. Карточки лички, архива и rich-message используют один `profileText`. Ранее отправленные карточки обновляются существующим воркером caption maintenance без повторной загрузки фотографий и без изменения исходного JSON.

После новой опубликованной версии отдельный пост поясняет разницу с предыдущей подтверждённой публикацией того же профиля. Он показывает изменившиеся поля, Premium, фотографии или миниатюры. Расстояние и состояние реакции наблюдателя не считаются изменениями анкеты. Формулировка описывает разницу ответов сервера, а не приписывает человеку ручное редактирование.

Сохранённый успешный ответ `/GPT/checkCompatibility` появляется отдельным постом в существующем треде. Явная однозначная оценка совместимости может отображаться в заголовке; это цитата из ответа Jardulik, не новая числовая метрика БД. Исходный `content` помещается в свёрнутую цитату без редактирования. Если ответ превышает лимит Telegram, пост содержит точное начало, явное указание продолжения и кнопку полного JSON в личку владельцу. Экспорт сохраняет точные байты `response_body` в `.json`.

Эти отправители входят в роль `serve-poster`, читают только сохранённые данные и не запускают дополнительные запросы GPT. Публикация расчётов пока ограничена `Config.OwnerID` и текущей привязкой его Jardulik-аккаунта. Полный JSON доступен тому же владельцу; чужой пользователь и прежний upstream аккаунт не проходят проверку callback.

Уведомления об изменениях и расчётах используют отдельные журналы отправки. Подтверждённая отправка содержит Telegram message ID; незавершённая подготовка безопасно возобновляется, а неопределённый результат HTTP сохраняется для сверки без автоматического повторного поста. Фактическая очередь использует общий архивный mutex и групповой лимит Telegram.

Пока анкета недоступна или ожидает доставки событие доступности, расчёты и пояснения не добавляются в её тред. Это сохраняет уведомление о недоступности последним. Существующие посты и архивы не удаляются.

Новые таблицы целиком входят в SQLite-бэкап. Ежедневный fingerprint по-прежнему меняется от исходных анкет и GPT-ответов; повторные попытки доставки не создают бэкап без новых данных.
