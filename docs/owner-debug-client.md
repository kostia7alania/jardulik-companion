# Личный API-клиент Jardulik

Публичный [Swagger-справочник](https://kostia7alania.ru/jardulik-companion-site/swagger/) и [OpenAPI JSON](https://kostia7alania.ru/jardulik-companion-site/swagger/openapi.json) описывают API. Личный клиент открывается через Go-сервис и использует текущую сессию основного владельца. Bearer, обновление токена и настроенный User-Agent добавляет бэк.

## Запуск

Клиент выключен по умолчанию. Для включения в окружении `jardulik-companion.service` задаётся:

```dotenv
JARDULIK_DEBUG_LISTEN=127.0.0.1:8788
```

После перезапуска `bot-parser` поднимает HTTP на loopback. Роль `poster` этот сервер не запускает. С Mac подключение идёт через существующий SSH:

```sh
ssh -N -L 127.0.0.1:8788:127.0.0.1:8788 sg-1gb
```

Пока туннель работает, открой [http://127.0.0.1:8788/](http://127.0.0.1:8788/). Страница получает `GET /debug/context`: текущий Jardulik ID, состояние подключения и nonce. Затем Swagger направляет запросы на локальный `/api` и добавляет `X-Jardulik-Debug`. Nonce меняется при перезапуске сервиса; достаточно обновить страницу.

## Доступные запросы

| Метод | Путь | Данные |
| --- | --- | --- |
| GET | `/api/user/getMe` | Собственная полная модель аккаунта |
| GET | `/api/photos/user/<own ID>` | Собственные записи фотографий |
| GET | `/api/user/getUser` | `targetUserId` собственной или уже известной аккаунту анкеты |
| GET | `/api/user/getUsers` | Выдача с фильтрами, страницей и необязательным `isMan` |
| GET | `/api/user/getReactUsers` | Входящие или взаимные реакции |
| GET | `/api/orders/type` | Варианты тарифа по `type` |
| POST | `/api/GPT/checkCompatibility` | `targetUserId` для расчёта совместимости |
| POST | `/api/reactions/addNew` | Ручная реакция на `userId` |

Это allowlist: остальные пути, методы и неподдерживаемые поля отклоняются локально. `userId` владельца в GET, `viewerUserId` и `fromUserId` бэк подставляет из сессии. Если передан другой ID владельца, запрос не уходит в Jardulik. Для цели используется отдельный `targetUserId` или `userId` реакции. Максимальный `pageSize` равен 150 для выдачи и 1000 для списка реакций. Эффект фильтра `isMan` этим клиентом не гарантируется.

В Swagger запрос выполняется вручную через `Try it out` → `Execute`. Открытие страницы и раскрытие метода ничего не отправляют в Jardulik. Перед POST бэк проверяет текущий аккаунт, состояние заморозки и свежую целевую анкету 18+.

## Реакции и повторные запросы

Для `/reactions/addNew` требуется действующее `ALLOW_REACTIONS=true`. Подтверждённые значения `reactionType`:

- `1`: Like. Использует общий журнал `actions`, проверку повторов и личный скользящий лимит вместе с ботом и автолайкером.
- `2`: Dislike.
- `3`: Super, или Огонь. Текст вводится вручную, после trim он должен быть непустым и не длиннее 500 UTF-16 единиц. Автоматические приветствия не запускаются.
- `4`: Delete; бэк согласует `isDeleted=true`.

Для Dislike, Super и Delete запросы и результаты записываются отдельно в аудит `debug_api_calls`; они не становятся обычными Like в `actions`. Баланс Огонь `fire` и его серверные ограничения относятся к Jardulik, а не к лимиту обычных лайков Companion. Период пополнения не установлен.

Каждый ручной POST получает `X-Jardulik-Request-Id`. Повтор того же ID с тем же аккаунтом, поколением, путём и телом возвращает сохранённый ответ для состояний `received`/`rejected`; заголовок `X-Jardulik-Debug-Replay: true` это отмечает. Повтор ID с другим запросом отклоняется. Незавершённый или неизвестный результат блокирует повтор для той же цели и типа действия, включая запрос с новым ID. После перезапуска оставшиеся `sending` становятся `unknown`. POST автоматически не повторяется после 401 или сетевого сбоя.

Пауза владельца или недоступная сессия блокируют обращения. После 401 у GET допускается одно штатное обновление токена и повторное чтение; окончательный 401 переводит сессию в переподключение. POST после 401 не повторяется. 403, 429 и challenge приостанавливают работу. Неизвестный исход POST также ставит аккаунт на паузу. Интерфейс показывает фактический HTTP-ответ либо локальную ошибку проверки; результат не считается успешным только из-за нажатия Execute.

## Совместимость и исходные ответы

Для GPT принимаются только `targetUserId` и собственный `fromUserId`, который можно не указывать. Модель запроса не переключается этим endpoint. Точное тело исходящего запроса, ответа и статус попадают в `debug_api_calls`. Ответ GPT и оба клиентских снимка сохраняются отдельно в `profile_analyses`; сообщённое поле `model` берётся из ответа, текстовый процент не превращается в числовую метрику. Исходный RawJSON анкеты сохраняется отдельно. Эти записи участвуют в ежедневном fingerprint бэкапа.

Заголовок `X-Jardulik-Debug-State` показывает состояние попытки; `X-Jardulik-Analysis-State: saved` подтверждает запись GPT-результата, `not_saved` означает, что запись анализа не подтверждена. Лимит тела POST равен 1 МиБ, ответа 2 МиБ; сетевой запрос ограничен 90 секундами.

## Известное ограничение обычного Like

При non-2xx от Jardulik существующий `LikeGuarded` не возвращает исходное тело ошибки в debug-прокси. Личный клиент в этом случае выдаёт `502 upstream_result_unconfirmed`, а аудит получает неизвестный результат без исходного тела. Такой Like автоматически не повторяется. Эта оговорка относится к ветке обычного Like; GET и прямой GPT POST используют другой путь чтения ответа.
