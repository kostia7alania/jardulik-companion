## Модели и поля

`getMe` дополнительно содержит балансы `fire`/`clean`, настройки поиска, приватности, статус заморозки и дату Premium. Обычный `getUser` возвращает поля отображаемой анкеты; отсутствие в нём этих полей ожидаемо для другой DTO.

- `isMain`: главное фото. Frontend выбирает `find(photo => photo.isMain) ?? photos[0]`; при загрузке первого слота передаёт `true`.
- `sort`: позиция фотографии. В собственном профиле используются слоты 0, 1, 2.
- `moderated`: UI трактует false как ожидание модерации, переход к true как одобрение.
- `createDate`: у собственной фотографии `2026-08-23T06:08:53`. Frontend это поле не читает. Похоже на время создания серверной записи, но ни дата съёмки EXIF, ни часовой пояс этим не установлены.
- `matchPercent`: у собственной фотографии `51.92409`. Frontend поле не читает; семантика и шкала не раскрыты. Гипотеза сравнения с селфи не подтверждена. Это поле объекта фото, а не установленный GPT-рейтинг.

`GET /photos/user/{id}` в просмотренной сборке вызывается только с собственным `myId`: собственный профиль и своё фото в экране взаимности. Фотография другого участника берётся из другого состояния, не через `jC(targetId)`.

В content оценка 75% является частью текста, отдельного score-поля нет. Текст включает астрологию/нумерологию и внутренне противоречивую арифметику: объявляет число 8, хотя приведённый им расчёт заканчивается 5. В свою числовую метрику эту строку автоматически не превращаем.

В штатном frontend запрос содержит только fromUserId и targetUserId; модель, prompt и temperature не передаются. Клиент ждёт полный JSON, затем имитирует печать текста. Переключение модели у Jardulik не подтверждено. Для отдельного собственного OpenAI-клиента модель задаётся полем `model` в запросе Responses API: https://developers.openai.com/api/docs/quickstart . Собственный платный вызов OpenAI не выполнялся.

`import-analysis` сохраняет точное тело ответа и запроса, оба клиентских снимка и сообщённую модель в отдельной append-only `profile_analyses`. Снимки не являются неизвестным внутренним prompt Jardulik. Поколение исходной HTTP-сессии отдельный helper не записал: для этого импорта явно `generation="not_recorded"`. Время анализа берётся из начала соответствующего HTTP-запроса. В исходный RawJSON анкеты результат не добавляется; повтор файла идемпотентен. ## Реакции и лимиты

Подтверждён клиентский enum: `Like=1`, `Dislike=2`, `Super=3`, `Delete=4`; 0 отсутствует. Удаление дополнительно отправляет `isDeleted:true`. У цели поле `userId`, у отправителя `fromUserId`.

Огонь требует непустого текста после trim, максимум 500 UTF-16 единиц. Штатный обычный Like отправляет пустую строку. Массовые приветствия не включались. Ответ `MessageKind=-2` означает отсутствие Огонь, `-3` требует Premium, `-1` содержит ограничение свайпов и может сообщить HoursLeft/MinutesLeft. IsLast при отказе означает конец анкет.

`fire` и `clean` показывают текущие балансы, не период пополнения. Клиент получает варианты week/month с сервера через `/orders/type?userId=<own>&type=1`. Норма 50 в день или 60 в месяц пока не подтверждена. Чистый лист `/user/clean` для проверки не вызывался: UI описывает сброс свайпов, лайков и взаимностей.
