# Два тестовых просмотра анкеты

`serve-miniapp` запускает отдельный HTTP-режим того же Go-бинарника. Он не запускает polling, парсер, GPT или реакции. Тест доступен только `OWNER_TELEGRAM_ID`.

- `/viewer?id=17053`: наш компактный просмотрщик сохранённой анкеты, оригинальные фото, полный текст и JSON.
- `/mutuals?targetUserId=17053&noCheck=1`: проверенная текущая сборка интерфейса Jardulik через наш адаптер.

Оба адреса передаются как `web_app`-кнопки Companion. Сервер проверяет HMAC `initData` нашим bot token, Telegram ID владельца и возраст запуска до 10 минут. Токен адаптера и старых ссылок без номера версии привязан к владельцу, аккаунту Jardulik, поколению сессии и конкретной сохранённой анкете. Настоящие access/refresh токены Jardulik в браузер не возвращаются.

Адаптер оригинального UI заменяет только две строки API origin и одно тело bootstrap login в сборке с фиксированным SHA. Локальный bootstrap выдаёт `code=200` и локальный bridge JWT после проверки настоящего собственного `getMe`; это ответ адаптера, а не изменённый ответ Jardulik. Остальные разрешённые ответы API возвращаются без изменения. Premium и freezeState берутся из настоящего ответа. Изменения профиля, реакции, GPT, платежи и получение контактов запрещены в этом HTTP-режиме.

Наш просмотрщик читает точный сохранённый JSON и общие Go-форматтеры. Медиа доступны только с локальным Bearer, из записей выбранной версии и фиксированных SHA-файлов. Токены не добавляются в URL. Публичные HTML/JS/CSS не содержат приватных данных; исходник поставщика проверяется SHA, путь и объём кеша ограничены. Устаревший или заменённый upstream HTML/entry требует проверки, вместо автоматической загрузки другой сборки.

Режим запускается в изолированном контейнере на сети `proxy`, без опубликованного порта хоста. Используется уже установленный runtime image, поверх которого монтируется статический Go-бинарник; дополнительных Go- и frontend-зависимостей нет. HTTPS даёт существующий Traefik. `deploy/miniapp-compose.yml` требует явных UID/GID, пути к проверенному бинарнику конкретной версии и public host/origin; секреты остаются в серверном env. HTTP-режим можно обновить отдельно от трёх основных процессов.

Для теста выбран проверенный DNS-адрес `jardulik.103.125.217.199.sslip.io`, указывающий на VPS. Он требует отдельного HTTP Host router и исключения только этого нового SNI из существующего TCP catchall. Остальные SNI и сервисы сохраняют прежний маршрут. Исходная конфигурация и точный rollback сохраняются до изменения. Браузерная проверка обоих вариантов и состояние TLS фиксируются после выкладки отдельно от локальных тестов.


## Открытие архивной версии

На ZIP сохранённой версии в операторском форуме появляется кнопка `Открыть сохранённую анкету`, когда в окружении бота и постера настроен адрес Mini App. Бот сверяет владельца, чат, тему и ID сообщения с квитанцией этого ZIP, затем отправляет в личку кнопку Companion. Ссылка содержит ID анкеты и сохранённой версии. После проверки Telegram `initData` сервер закрепляет версию за токеном, показывает её фото, текст и исходный JSON. Токен этого просмотра даёт доступ к выбранному снимку и его фото. Сохранённая версия открывается даже при паузе или отключении Jardulik. Общая кнопка Jardulik продолжает открывать официальное приложение.

Кнопка появляется на новых ZIP и при штатном обновлении их кнопок. Для одного уже подтверждённого ZIP команда `jardulik refresh-archive-viewer-control <versionId>` редактирует только кнопки и сверяет квитанцию Telegram. При включённом суточном цикле команда использует общую блокировку и интервал отправки постера. В режиме без суточного цикла требуется пауза архивного воркера. Старые сообщения не меняются автоматически. Прежние ссылки просмотрщика с одним ID анкеты продолжают открывать последнюю сохранённую версию.

## Проверка 11.11.2026

- Основные процессы: `e50f190694e2bd44d4ba22770dc940819c792300`; отдельный Mini App: `11ca7af80e1e4e628f75044c87befd12c29d8579`.
- HTTPS проверен без отключения проверки сертификата. Публичный shell и адаптированный pinned bundle возвращают 200, приватный профиль без авторизации возвращает 401. Порт контейнера не опубликован на хосте.
- Go-команда `miniapp-test-card 17053` отправила одну карточку в личку владельца, message ID `260`. Обе кнопки реально открыты в Telegram Web: `/viewer?id=17053` показал выбранное фото, полное описание и свёрнутый исходный JSON; оригинальный UI после входа оказался на `/mutuals?targetUserId=17053&isSuper=0` и показал ту же анкету.
- Старая сессия не прошла refresh. Тот же аккаунт переподключён свежим официальным запуском через stdin, без записи launch URL в файл. API подтвердил пользователя `5696`, Premium `type=1` и окончание `2026-12-07T20:39:45+04:00`.
- После тестов: одна квитанция тестовой карточки, ноль новых реакций и ноль изменений сохранённых raw JSON. Автолайки выключены. Снимок памяти Mini App во время проверки: 12,23 МиБ при лимите 128 МиБ; это не пиковое измерение.
- Полный race-набор и vet прошли для основного релиза. Сбой загрузки JS воспроизведён на VPS (`Accept` → HTTP 406), исправление покрыто регрессией и проверено группой Mini App race-тестов, vet и повторным живым запуском.
